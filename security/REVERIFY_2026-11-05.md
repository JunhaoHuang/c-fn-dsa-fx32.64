# 2026-11-05 全组件侧信道安全性复核（NI / SNI / MIMO-SNI / PINI）

复核对象：工作树中的 `mask160.c`、`mask_sampler.c`、`mask_mq.c`、
`mask_xpoly.c`、`mask_tree.c`、`sign_masked.c` 全部源码，以及
Clang 18.1.3 `-O2` 生成的 `mask160.o`。定义与组合定理见
[DEFINITIONS.md](DEFINITIONS.md)；可执行穷举见 [probe_check.py](probe_check.py)。

模型：两份额、`t = 1`、源码级 32 位 word-probing、IDEAL-RNG。带 `*` 的
结论都以理想随机数为前提；固定 LFSR 仍为 `DEMO ONLY`。

## 1. 复核结果摘要

1. **新发现一处机器码级 1-NI 失效（CONFIRMED）**：`mbit_to_mmod32()`
   中 `c = (a0 ^ rb0) ^ (a1 ^ rb1)` 没有值屏障，Clang 先计算
   `a->share[1] ^ a->share[0]`（`mask160.o` 偏移 `dd87/dd8a`、`ddc5/ddc8`：
   `mov 0x4(%rbx),%edi; xor (%rbx),%edi`），即把 **符号位/进位位的未掩码
   重构值** 放进寄存器。该 gadget 由 `mi32_to_mmod32()` →
   `mmpoly_from_mi32()` 调用，签名核心用它转换 `tree.dz`（左树样本 `z0`）、
   `z1`、`A`、`B`，因此泄漏的是秘密采样向量系数的符号位。源码级证明本身
   正确，失效完全来自编译器重结合；修复只需两个值屏障（见第 5 节）。
2. **既有 `REVIEW` 项全部闭合为条件 1-SNI\* 或 1-PINI\***：
   inverse/division/sqrt、expm、`mi32_poly_sqnorm_le`、
   `mi32_signature_is_acceptable`、FFT/split/merge/LDL/iXadj、复数乘法、
   动态树值路径、签名连接层。闭合依据是第 2 节的单探针组合定理，而不是
   原文档要求的 MIMO-SNI 图：逐份额线性多输出层本来就不是 MIMO-SNI，
   也不需要是；它们是 PINI，PINI 任意组合保持 probing 安全。
3. **所有 `ring_mul`/`ring_mul192`/`mmod32_mul` 调用点均满足别名规则**
   （两操作数无仅经线性层的公共祖先；每个站点至少一个操作数份额新鲜）。
   逐站点清单见第 3 节。
4. **sampler Boolean 子图的 MIMO-1-SNI\* 得到穷举确认**：`eq`/`lt` 任意
   份额对联合 0-share。
5. **最大实际风险不在 gadget 内部而在边界**：`mrx160_sampler_z()` 的
   BaseSampler 候选 `z0`、符号位 `b`、`zi` 和 PRNG 字节 `lo/hi` 是明文局部
   变量，再加上公开的 accept 位，一个探针即可得到每个被接受样本的
   `z - floor(mu)` 与符号位。这正是 Guerreau et al.（TCHES 2022）与
   Zhang et al.（EUROCRYPT 2023）对 Falcon 的实际密钥恢复攻击所利用的量。
6. **可组合性结论**：在 IDEAL-RNG + 源码级模型下，除第 5 条边界、显式打开
   位和第 1 条编译器失效外，整个掩码值路径可组合为 1-NI（1-probing 安全），
   各 gadget 出口为 1-SNI。该结论不覆盖 transition 泄漏、机器码（已有一例
   反例）、固定 LFSR 与 hedge/PRNG 明文边界。

## 2. 采用的组合框架（为何不再需要 FFT/LDL 的 MIMO-SNI 图）

`t = 1` 时单个探针只落在一个 gadget 内；其模拟请求沿逐份额线性层回溯时
份额索引保持不变，在任何输出刷新 gadget（A2B/B2A/refresh/mul/select 等）
处终止。因此整体 1-NI 只可能被一种结构破坏：双输入非 PINI 乘法
（`ring_mul*`、`mmod32_mul`）的内部项 `a_0 * b_1` 把两条请求回溯到同一个
sharing 的两个份额。这就是 `ring_mul(a, a)` 反例的全部本质。

于是复核归结为两件事：（i）每个 gadget 单独 1-NI 且输出份额 0-share
（第 4 节矩阵）；（ii）每个乘法调用点满足别名规则（第 3 节）。满足后，
整个电路是 PINI 子 gadget 的组合，因而 1-probing 安全；输出来自刷新
gadget 的部分是 1-SNI。多输出线性层（FFT 蝶形、split/merge、LDL 的 `d/e`、
NTT 蝶形、CRT 映射）作为 PINI 节点参与组合，不需要也不满足 MIMO-SNI。
MIMO-SNI 仅在把一个多输出 gadget当作 **SNI 黑盒** 使用时才需要；本仓库
只有 `mb64_compare_byte()` 处于这种位置，且已穷举确认。

## 3. 乘法调用点别名审计

规则：`M(a, b)` 中 `a`、`b` 不得有仅经逐份额线性操作可达的公共祖先；
满足的充分条件是某一操作数是“份额新鲜”的（每个份额含有上游刷新/乘法
输出的新鲜随机量）。`mrx160_mul_wide()` 在两个输入上各做一次独立 SNI
A2B，因此对任意输入（含 `a == b`）都安全，并且本身是 1-PINI。

| 调用点 | 操作数 | 份额新鲜来源 | 结论 |
|---|---|---|---|
| `mrx160_inv_spec`: `mul(t,x,ub)` | `x = c48 - mul_public_fast(ub)` / `x += t` | `x` 含上游 SNI 输出 | OK |
| `mrx160_inv_spec`: `mul(t,y,x)` | `y = one - mul(x,ub)` | `y` 含 SNI 输出 | OK |
| `mrx160_inv_spec`: `mul(d,ua,x)` | `ua = b2a(...)` | `ua` 为 B2A 输出 | OK |
| `mrx160_div_spec` | 同上，末尾 `mul_wide` | 同上 | OK |
| `mrx160_sqrt_spec`: `sqr(y,x)` | 内部双 refresh | — | OK |
| `mrx160_sqrt_spec`: `mul(y,b,y)` | `b = b2a(...)`, `y = sqr(...)` | 两者皆 SNI 输出 | OK |
| `mrx160_sqrt_spec`: `mul(x,y,x)` | `y = half(...)` | SNI 输出 | OK |
| `mrx160_expm_p63`: `mul_u64_hi(bp,y,x)` ×12 | `y = C_i - b2a(bp)` | `y` 含 B2A 输出（首轮 `y` 公开） | OK |
| `mrx160_expm_p63`: `mul_u64_hi(d,y,ccs)` | 同上 | OK | OK |
| `mrx160_sampler_z`: `sqr(dss,isigma)`, `sqr(x,x)` | 内部 refresh | — | OK |
| `mrx160_sampler_z`: `mul(x,x,dss)` | `x = sqr(...)`, `dss = half_positive(...)` | 两者皆 SNI 输出 | OK |
| `mi32_square_add`: `mul_wide(y,x,x)` | 同一 sharing 双输入 | `mul_wide` 入口双 A2B | OK |
| `mcomplex_mul` ×3 | `mul_wide` | 入口双 A2B | OK |
| `mxpoly_div_selfadj_spec_fft`: `mul_wide(a[i],inv)` ×2 | `inv = inv_spec(...)` | SNI 输出 | OK |

未发现任何违反别名规则的站点。`mrx160_sqr()`、`mul_wide()` 的别名安全性
由 `probe_check.py` 的 `ring_mul(a,a)`（FAIL）与 `mrx160_sqr`（通过）对照
用例佐证。

## 5. 发现与建议（按风险排序）

### F1. `mbit_to_mmod32()` 机器码失效（CONFIRMED，修复简单）

源码：

```c
uint32_t c = ((a->share[0] & 1) ^ rb0)
	^ ((a->share[1] & 1) ^ rb1);
```

Clang 18 `-O2` 对 `mask160.o` 生成 `mov 0x4(%rbx),%edi; xor (%rbx),%edi`，
先形成 `share[1] ^ share[0]`。建议补丁：

```c
uint32_t c0 = (a->share[0] & 1) ^ rb0;
value_barrier_u32(&c0);
uint32_t c1 = (a->share[1] & 1) ^ rb1;
value_barrier_u32(&c1);
uint32_t c = c0 ^ c1;
```

修复后需：重新 objdump 确认；把该模式加入 `probe_check.py`（已有
`COMPILER:a0^a1` 线路作为负面回归）；在发布门槛中增加“同一表达式内不得
同时出现两个份额”的静态扫描（当前 grep 规则只能捕获同一行，本例跨行）。

### F2. BaseSampler 候选与符号位明文（设计边界，实际攻击面最大）

`mrx160_sampler_z()` 中 `lo`、`hi`、`z0`、`b`、`zi`、`zr`、`z0r` 为明文，
`mrx160_share_rx()` 才开始分享。配合公开的 accept 位，单探针得到被接受
样本的 `z - floor(mu)` 与符号位。要闭合需要：掩码 BaseSampler（对 18 个
72 位阈值做掩码比较，可直接复用 `mb64_compare_byte` 风格比较器）、掩码
符号位与掩码 `b + (2b-1) z0` 组合、以及 PRNG 字节直接以 Boolean 分享形式
进入比较器。这会改变随机字节的消费方式，需要与“比特精确兼容”目标取舍。

### F3. 打开位的泄漏契约

- `O_accept`（SamplerZ）：接受概率 `exp(-x)·ccs` 依赖秘密 `x`；泄漏的
  是重试次数，与参考实现一致，可引用 Howe et al. 2020 的等时性论证。
- `O_eq`（BerExp 逐字节）：在 PRNG 字节保密的前提下，`eq` 是与秘密独立的
  Bernoulli(1/256)，单独打开不泄漏；但 PRNG 字节是明文，探针读到 `w` 后
  `eq = 1` 即给出阈值的一个字节。trace-oblivious 配置需固定比较 8 字节。
- `O_keyok`、每次尝试的 `O_accept`：公开信息（签名是否输出），无额外泄漏。

### F4. 模型外：transition 泄漏

两份额在 `mrx160`/`mb160` 结构体中相邻存放，且大量 `for (j = 0; j < 2; j++)`
循环用同一段代码依次处理两个份额；在 Cortex-M4 这类目标上，同一寄存器或
总线先后承载 `x_0`、`x_1` 会以 Hamming 距离泄漏 `x_0 ^ x_1`（Boolean 份额
即秘密本身）。源码级 NI/SNI 结论对此无效。缓解：份额分离存放、share-major
顺序（`mask_mq.c` 的 NTT 已这样做）、在份额切换处清零寄存器、并用 TVLA
在目标上验证。

### F5. 随机源与明文边界（已知，未变）

固定 LFSR、hedge token、seedbuf、`mu`、masked-key 种子展开均为已记录的
`DEMO ONLY`/`BOUNDARY` 项。

## 6. 组合性总结

| 问题 | 结论 |
|---|---|
| 各 gadget 是否能安全组合 | **能**（IDEAL-RNG、源码级、`t = 1`）。所有非乘法 gadget 为 1-PINI；五个乘法 gadget 为 1-SNI 且每个调用点满足别名规则，故每个调用点连同上游刷新构成 PINI 子 gadget。PINI 组合定理给出整体 1-probing 安全；以刷新 gadget 收尾的路径为 1-SNI。 |
| FFT/LDL/split/merge 是否需要 MIMO-SNI | **不需要**。它们是逐份额线性层，是 PINI 而非（MIMO-）SNI；原 `REVIEW` 义务应改写为“PINI 组合 + 乘法别名规则”，本次已逐站点完成。 |
| 哪些组件真的是 MIMO-SNI | 仅 `mb64_compare_byte()`（穷举确认）。 |
| 端到端能否声明 1-SNI | **不能**，原因依次为：F1 机器码失效、F2 明文采样边界、F3 显式打开、F5 随机源与 hedge 边界、F4 模型外泄漏。修复 F1 后，“值路径在源码级模型下 1-NI、带显式泄漏契约 {accept, eq, retry, key_ok}”是可以写进接口的最大声明；F2 是从研究原型走向可发布实现的首要工作。 |
