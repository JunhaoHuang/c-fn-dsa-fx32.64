# 安全模型与证明规则

## 1. 被证明的对象

实现固定为两个份额，因此掩码阶数为 `t = 1`。

- 算术份额：`x = x0 + x1 mod 2^k`，或 `x = x0 + x1 mod q`；
- 布尔份额：`x = x0 XOR x1`；
- 一个探针读取一个完整的 32 位 C 中间字或份额字；
- 多字运算中的进位、借位和编译器生成的临时寄存器也必须视为候选探针。

最后一点意味着仅对 C 左值作证明还不够。若一个表达式可能被编译为先组合
两个秘密相关项、再加入随机数，则必须通过固定求值顺序、值屏障和目标汇编
审查闭合证明。

## 2. 1-NI

对 gadget `G`，若任意至多一个内部或输出探针的分布，都能由一个模拟器仅凭
每个掩码输入至多一个份额完美生成，则称 `G` 为 1-NI。

这里“每个输入至多一个份额”允许模拟器例如读取 `a0` 和 `b1`，但不能同时
读取 `a0,a1` 或 `b0,b1`。公开常数和公开控制参数可被模拟器自由使用。

## 3. 1-SNI

设内部探针数为 `t_int`，输出探针数为 `t_out`，且
`t_int + t_out <= 1`。若所有这些观察都能由至多 `t_int` 个、而不是
`t_int+t_out` 个输入份额模拟，则 gadget 是 1-SNI。

对一阶情形，这等价于同时满足：

1. 一个内部探针至多需要每个输入的一个份额；
2. 单独观察任意一个输出份额时，不需要任何输入份额。

所以“逐份额线性运算”通常是 1-NI，但不是独立的 1-SNI gadget：例如
`z0 = x0 + y0` 的输出探针直接依赖固定输入份额。若输出经过新鲜 refresh，
第二个条件才可能成立。

## 4. MIMO-SNI

FFT split、LDL 和动态树有多个掩码输入与多个掩码输出。对这类组件，普通
单输出 SNI 不足以描述扇出。MIMO-SNI 要求：在总输出探针预算为 `t_out`
时，每组输出上至多放置 `t_out` 个探针，同时仍只能用 `t_int` 个输入份额
模拟。

本审计只在能逐路径证明时声明 MIMO-SNI。对包含未刷新复制、一个输入向多个
输出扇出或已失败子 gadget 的组件，不把“每个输出看起来被分享”当作
MIMO-SNI 证明。

## 5. 随机数前提

所有带 `*` 的正面结论要求：

- 每次 gadget 所需的随机 32 位字均匀；
- 不同随机字相互独立；
- 与所有秘密、输入份额和签名随机流独立；
- 已消费的随机字或随机位永不复用；
- 攻击者事前不知道这些随机字。

当前 `fndsa_mask_rng_init_demo()` 使用固定 LFSR-127 状态，并在每个顶层调用
重新初始化。reservoir 虽然避免同一次调用内重复消费位，却不能把确定性序列
变成秘密的独立均匀随机数。因此当前 demo 不满足这些前提。正面证明只能解释
“把 RNG 替换为满足前提的后端后，该局部公式具有什么性质”。

## 6. 公开、秘密与解密边界

以下量按公开处理：数组长度、`logn`、递归深度、FFT 索引、twiddle 常数、
模数以及错误参数检查。

以下量按秘密处理：私钥系数、所有由私钥导出的 Gram/LDL/FFT 值、采样中心、
标准差相关量、接受概率和样本值。签名 PRNG 输出在本审计中也不默认公开；
若实现把它作为可观察量，则需要单独证明与最终公开签名联合观察仍安全。

`mrx160_open_rx()`、`mi32_open_compat()`、`mmod32_open()`、
`mbit_open_compat()` 和 `mb64_open_compat()` 是显式打开函数，不属于保密
gadget。若调用者打开一个秘密相关判定位，则整个调用者只能在明确的泄漏/解密
契约下分析，不能直接声明 NI/SNI。

`mrx160_share_rx()`、`mi32_share()`、`mmod32_share()` 和私钥导入函数接收
明文秘密。它们可以生成分布正确的份额，但明文输入和函数内明文副本本身可被
探测，因此只能放在可信置备边界外。

## 7. 源级模型不覆盖的现象

本证明不自动覆盖：

- glitch-extended probing；
- 相邻寄存器转换和 Hamming-distance 泄漏；
- cache、分支预测、可变循环次数和总执行时间；
- 故障注入；
- 高阶或多迹统计攻击；
- 编译器在 LTO、寄存器分配或指令选择时合并份额；
- 固定 LFSR 的状态恢复和跨调用相关性。

因此，一条源码级 1-SNI 结论不是生产侧信道安全认证。至少还需要真实随机后端、
固定编译配置、每目标汇编审查以及泄漏测试；后两者也不能替代数学证明。

## 8. 组合规则

本目录采用以下保守组合规则：

1. 逐份额线性层保持 1-NI；
2. SNI gadget 的输出可安全送入后续 NI/SNI gadget；
3. 一个普通 NI 输出若被多个非 SNI gadget 重用，不能仅凭局部证明推出组合 NI；
4. 整体输出若来自 SNI refresh，且此前整个组合已经是 NI，则可进一步证明 SNI；
5. 任意子 gadget 存在 `FAIL-1-NI` 时，所有可达上层组件均不能通过局部组合定理
   获得 NI/SNI；末尾 refresh 不能擦除已经被内部探针读到的历史值。

这些规则与 SNI 作为可组合 probing 安全条件的原始定义以及当前 FALCON floor
论文采用的单路径组合图方法一致。参考资料列在 [GADGET_PROOFS.md](GADGET_PROOFS.md)
末尾。
